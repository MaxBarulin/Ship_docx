# Круизное судно — параметрическая модель

Проект под конкурсное задание УЖЦ ОСК 2026: круизное судно для рек и озёр РФ,
не менее 200 пассажиров, автономность от 10 суток.

Здесь лежит блок 3D-дизайна: судно целиком и каюты четырёх категорий. Обе
модели читают размеры из одного файла, поэтому судно и каюты не могут
разойтись — каюты нарезаны из той же сетки, по которой построена надстройка.

## Судно

| Характеристика | Значение |
|---|---|
| Длина наибольшая / по КВЛ | 141.0 / 139.1 м |
| Ширина наибольшая | 16.84 м |
| Осадка | 3.2 м |
| Водоизмещение | 6253 т |
| Коэффициент общей полноты | 0.836 |
| Высота с заваленной мачтой | 14.2 м |
| Палуб / из них с каютами | 5 / 3 |
| Кают / пассажиров | 138 / 276 |

Водоизмещение считается не по коэффициенту полноты, а по геометрии: подводная
часть отсекается плоскостью осадки, и меряется её объём. Ширина берётся
фактическим габаритом модели — сглаженный лофт выпучивает борт между
шпангоутами шире, чем стоит в таблице, и на запасе до стенки шлюза это видно.

```bash
python scripts/vessel_report.py            # виды судна и таблица ТТХ
python scripts/vessel_report.py --no-render # только цифры
```

Отчёт печатает и проверки по ограничениям трассы: ширина в камере шлюза,
осадка на гарантированной глубине, высота под мостами. Последняя проверка
намеренно показывает отказ с поднятой мачтой — на ЕГС мачту заваливают, и
модель обязана это фиксировать, а не скрывать.

Взрыв-схема (`src/vessel_exploded.py`) собирается из той же геометрии с
раздвинутыми ярусами — требование блока дизайн-проекта закрывается без
отдельной модели, которая могла бы разойтись со сборкой.

## Каюты

## Главное решение: одна модульная сетка

Каюты не нарисованы по отдельности — они нарезаны из одного шага сетки.
Цепочка обоснования идёт от того, что команда не выбирает:

```
камера шлюза ЕГС 17.6 м
  -> ширина корпуса 16.8 м (как у аналогов пр. 301/302 и PV300 — по той же причине)
  -> поперечная схема палубы: каюта 3.5 + коридор 1.6 + каюта 3.5
  -> глубина каюты 3.4 м в свету
  -> категория = число модулей по 1.30 м вдоль борта
```

| Категория | Модулей | Ширина | Площадь в свету | Требование КЗ |
|---|---|---|---|---|
| Эконом | 2 | 2.60 м | 8.50 м² | ≥ 8 м² ✓ |
| Стандарт | 3 | 3.90 м | 12.92 м² | ✓ |
| Бизнес | 4 | 5.20 м | 17.34 м² | ✓ |
| Люкс | 6 | 7.80 м | 26.18 м² + балкон | ✓ |

Одна сетка закрывает сразу два требования КЗ: рендеры четырёх категорий кают
и модульные решения для изменения количества и категорий кают. Категории
набираются на борту в любой комбинации, лишь бы сумма модулей сошлась.

Балкон люкса — не украшение: поперечная схема оставляет по 2.1 м променада
на каждый борт, люкс его и занимает.

## Что где лежит

```
src/lib/ship.py        размеры судна, шпангоуты и сетка кают — ЕДИНСТВЕННОЕ
                       место, где лежат числа
src/lib/hull.py        обводы корпуса, водоизмещение, проверки по трассе
src/lib/deckhouse.py   надстройка, палубы, рубка, шлюпки, трап, панели
src/lib/vessel.py      судно в сборе, оно же взрыв-схема
src/lib/palette.py     отделка кают: цвета и отклик поверхностей на свет
src/lib/furniture.py   библиотека судовой мебели и санблока
src/lib/cabin.py       оболочка каюты и четыре планировки
src/hull.py            корпус отдельной моделью
src/vessel.py          судно
src/vessel_exploded.py взрыв-схема
src/cabin_*.py         четыре каюты
STEP/                  геометрия с полным деревом и русскими именами частей
GLB/                   то же с материалами, для внешнего рендера
renders/               виды, пересобираются одной командой
scripts/render_cabins.py
scripts/vessel_report.py
```

## Как пересобрать

```bash
python src/cabin_econom.py                  # одна каюта: STEP + GLB
python scripts/render_cabins.py             # все рендеры и сводные листы
python scripts/render_cabins.py lux         # только одна категория
```

Проверка, что мебель не стоит внутри мебели — обязательна после каждой правки
планировки, глазами такое не ловится:

```bash
.venv/bin/cadgen step inspect interfere STEP/cabin_lux.step --format text --tolerance 5000
```

Когда Андрей выдаст главные размерения, а Алексей — планы палуб, правится
`src/lib/ship.py` и всё пересобирается. Ни одна планировка не переписывается.

## Проверка вместимости

```bash
python -c "
import sys; sys.path.insert(0,'src')
from lib import ship
print(ship.capacity({'econom':10,'standard':8,'business':4,'lux':1}))"
```

Считает занятую длину борта и итоговую пассажировместимость — на случай
вопроса эксперта «а откуда 200 пассажиров».

## Установка инструмента

Геометрию считает [text-to-cad](https://github.com/earthtojake/text-to-cad)
(v0.5.1) — библиотека агентских скиллов для CAD. Скиллы лежат в
`.agents/skills/`, Claude Code видит их через `.claude/skills/`, состав
зафиксирован в `skills-lock.json`.

Окружение поднимается автоматически хуком `SessionStart`, вручную — так:

```bash
bash scripts/setup-cad.sh
```

Скрипт идемпотентен: с нуля около минуты, на готовом окружении — секунда.

Снимки и вьюер рисуются headless-Chromium через Playwright, а Playwright
запускает только ту сборку браузера, которую пинит его версия.
`scripts/ensure_chromium.py` разбирает оба случая: если браузер уже есть в
`PLAYWRIGHT_BROWSERS_PATH`, подбирает под него версию Playwright; иначе
скачивает нужную сборку.

Обновление скиллов — `npx skills add earthtojake/text-to-cad`; после него
сверьте пин `cadgen` в `requirements-cad.txt` с
`.agents/skills/cad/requirements.txt`.
